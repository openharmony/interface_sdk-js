# 鸿蒙多设备 API 行为差异知识库

> 本文档供 AI 在 ODK spec 阶段分析 API 的多设备支持能力和行为差异时学习参考。AI 通过读取 interface 仓库根目录的 AGENTS.md 发现并加载本文件。

---

## 1. 设备类型枚举

鸿蒙 API 支持以下 9 种设备类型：

| deviceModelName | 中文 | deviceModelId | 别名 |
|-----------------|------|---------------|------|
| `phone` | 手机 | 11 | phone, 手机, Phone |
| `tv` | 电视 | 12 | tv, TV, 电视, 智慧屏 |
| `tablet` | 平板 | 13 | tablet, 平板, Tablet |
| `2in1` | 二合一 | 14 | 2in1, 2 in 1, 二合一, PC/2in1 |
| `wearable` | 穿戴 | 15 | wearable, 穿戴, 手表, 手环 |
| `car` | 车机 | 16 | car, 车机, 车载 |
| `liteWearable` | 轻穿戴 | 17 | liteWearable, 轻穿戴, 轻量级穿戴 |

## 2. 设备支持范围判定

### 判定流程

1. 根据 API 的 `@syscap` 查询该系统能力支持的设备列表及各设备的 syscap 支持版本
2. 每个设备的起始版本 = MAX（三者按字符串原样比较，取最大者原值），版本号格式参见 [AGENTS-version-rules.md](./AGENTS-version-rules.md)：
   - **syscap 支持版本** ← 该设备在该系统能力下的 `apiLevel`
   - **API 引用版本** ← API 的 `@since` 版本号
   - **商用版本** ← 该设备的商用版本 `apiLevel`；查不到则仅取 MAX(前两者)
3. 无 `@syscap` 匹配 → 无法确定设备支持范围

### 禁止事项

- 不得臆造设备支持范围
- 无 syscap 匹配时不得自行填充设备列表
- 版本号不得低于计算值（禁止降级）

## 3. 差异行为类型

当 API 在不同设备上行为不一致时，用以下 8 种行为类型描述差异：

| 行为表现值 | 中文标签 | 含义 | 是否正常值 |
|-----------|---------|------|:----------:|
| `IMPLEMENT_CONSISTENT` | 功能正常，实现一致 | 设备支持且行为一致 | ✅ 正常值 |
| `IMPLEMENT_DIFF` | 功能正常，差异化实现 | 设备支持但自适应差异 | ✅ 正常值 |
| `RETURN_801_ERROR` | 返回 801 错误码 | 设备不支持时返回 801 | ❌ |
| `RETURN_BUSINESS_ERROR` | 返回业务错误码 | 返回业务定义的错误码 | ❌ |
| `NO_RESPONSE` | 不生效或无响应 | 调用后无效果 | ❌ |
| `RETURN_DEFAULT` | 返回模拟值或默认 | 返回模拟/默认数据 | ❌ |
| `RETURN_EMPTY` | 返回空值 | 返回 null/空 | ❌ |
| `OTHER` | 其他 | 其他行为（需补充说明） | ❌ |

---

## 4. 差异原因

| 原因值 | 适用场景 |
|--------|---------|
| 产品业务诉求 | 业务决策导致的差异 |
| 硬件差异导致 | 硬件能力不同 |
| 芯片差异导致 | 芯片平台不同 |
| 其他 | 其他原因（需说明） |

> **特殊规则**：当行为表现 = "功能正常，实现一致"时，差异原因固定为"无差异"，不可选其他值。

---

## 5. 设备移除规则

根据差异行为判定设备是否应从支持列表中移除：

- 差异行为**包含至少一个正常值**（`IMPLEMENT_CONSISTENT` 或 `IMPLEMENT_DIFF`）→ 设备**保留**
- 差异行为**不包含任何正常值** → 设备从支持列表中**移除**

### 判定逻辑

```
正常值集合 = {IMPLEMENT_CONSISTENT, IMPLEMENT_DIFF}
是否移除 = 该设备的差异行为列表中不包含任何正常值
```

### 判定示例

| 差异行为 | 是否移除 | 原因 |
|---------|---------|------|
| `IMPLEMENT_DIFF` | ❌ 保留 | 包含正常值，设备支持 |
| `IMPLEMENT_DIFF`, `RETURN_BUSINESS_ERROR` | ❌ 保留 | 包含正常值，设备在某些场景支持 |
| `RETURN_801_ERROR` | ✅ 移除 | 不包含正常值，设备不支持 |
| `RETURN_BUSINESS_ERROR`, `NO_RESPONSE` | ✅ 移除 | 不包含正常值，设备不支持 |
| `IMPLEMENT_CONSISTENT`, `NO_RESPONSE` | ❌ 保留 | 包含正常值 |

## 6. 自然语言解析规则

开发者用自然语言描述设备差异时，AI 需按以下规则解析为结构化数据：

### 解析流程

1. 开发者用自然语言描述（如"因硬件原因，不支持 tv，在 tv 上调用时会返回 801；不支持平板，在平板上调用无效果"）
2. AI 解析为结构化数据（设备类型、行为表现、差异原因、差异描述）
3. 以**中文列名**和**中文选项值**展示结果供开发者确认
4. 确认后才可落盘

### 解析字段

| 字段 | 规则 |
|------|------|
| 设备类型 (deviceModelName) | 九选一枚举值；支持中文别名自动映射 |
| 行为表现 (diffPerformance) | 八选一；用户原文别名映射到枚举值 |
| 差异原因 (diffReason) | 行为表现 = 实现一致 → 固定为"无差异"；其余四选一：产品业务诉求 / 硬件差异导致 / 芯片差异导致 / 其他 |
| 行为表现说明 (diffPerformanceDesc) | 仅当行为表现 = "其他"时必填；其余为空 |
| 差异描述 (diffDescription) | 从开发者原文中提取相关描述句/短语，不得编造 |

### 展示规则

- 展示时用中文列名（设备类型、行为表现、差异原因、差异描述）
- 展示时用中文选项值（如"返回801错误码"而非"RETURN_801_ERROR"）
- **禁止**展示 JSON 字段名和英文 value

### 展示示例

开发者输入：`因硬件原因，不支持tv，在tv上调用时会返回801；不支持平板，在平板上调用无效果`

AI 解析后展示：

| 设备类型 | 行为表现 | 差异原因 | 差异描述 |
|---------|---------|---------|---------|
| 电视 | 返回801错误码 | 硬件差异导致 | 在tv上调用时会返回801 |
| 平板 | 不生效或无响应 | 硬件差异导致 | 在平板上调用无效果 |

### 禁止事项

- 禁止编造开发者未描述的差异
- 禁止未确认即落盘
- 禁止展示字段名/英文 value
- 禁止硬编码设备类型别名（应从本文件 §1 的枚举表加载）

---

## 7. 合法默认值

当设备行为表现 = "功能正常，实现一致"（`IMPLEMENT_CONSISTENT`）时：

- 差异原因固定为 `无差异`
- 差异描述固定为 `无差异`（无值时自动填充）

此时该设备保留在支持列表中，且不触发"差异原因为空"错误。

---

## 8. 设备类型修改约束

修改已有 API 的设备支持时，遵守以下约束：

| 操作 | 是否允许 | 说明 |
|------|:--------:|------|
| 修改现有设备版本 | ✅ | 设备在支持列表中，修改 apiLevel |
| 新增设备（syscap 支持） | ✅ | 设备在 syscap 列表中但未生成 |
| 新增设备（syscap 不支持） | ❌ | 脚本直接拒绝，无法绕过 |
| 删除设备 | ✅ | 通过设置设备差异为非正常值实现 |
| 版本降级 | ❌ | 版本不得低于计算值 |
| 替换设备类型 | ❌ | 禁止将某设备类型替换为另一类型 |
