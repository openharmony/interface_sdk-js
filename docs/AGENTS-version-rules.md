# 鸿蒙 API 版本号规则

> 本文档供 AI 在 API 设计各阶段参考版本号格式规范。AI 通过读取 interface 仓库根目录的 AGENTS.md 发现并加载本文件。

---

## 版本号演进

鸿蒙 API 版本号经历了两个阶段：

- **API 26 之前（API 6 ~ 25）**：版本号为纯数字，如 `6`、`12`、`20`。
- **API 26 起（API 26 及以后）**：版本号升级为点分版本号（语义版本），如 `26.0.0`、`26.0.1`、`26.1.0`、`27.0.0`。

## 版本号格式

| 格式 | 示例 | 适用阶段 |
|------|------|---------|
| 数字版本 | `"12"`, `"13"`, `"20"` | API 26 之前 |
| 点分版本 | `"26.0.0"`, `"26.1.0"` | API 26 起 |

## API 版本与系统版本映射

从 API 26 起，API 版本号与系统版本存在映射关系：

| API 版本 | 系统版本 | 说明 |
|----------|---------|------|
| `26.0.0` | 7.0 | 基线版本 |
| `26.0.1` | 7.0 MR | 基线版本的维护发布（MR） |
| `26.1.0` | 7.1 | 次要版本迭代 |

映射规则：

- **主版本号**（如 `26` → `27`）对应系统大版本升级。
- **次版本号**（如 `26.1`）对应系统的 `.1` 次要版本。
- **修订号**（如 `26.0.1`）对应基线版本的 MR（Maintenance Release）。

## 版本号比较规则

- 起始版本 = MAX（多个版本按字符串原样比较，取最大者原值）
- 版本号不得低于计算值（禁止降级）
- 比较时注意纯数字与点分版本号属于不同阶段，不可混用比较规则
